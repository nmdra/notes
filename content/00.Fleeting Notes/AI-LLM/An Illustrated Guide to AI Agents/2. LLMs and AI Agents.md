> 
> ![[2. LLMs and AI Agents-1789652571117.webp]]

> - LLMs consume and produce **tokens**.
> - Generation is **autoregressive**: one token becomes part of the context for generating the next.

> - **Pre-training** produces a base model using next-token prediction.
> - **SFT** teaches instruction-following using prompt/completion examples.
> - **RLHF** optimizes based on preferences.
> - **RLVR** optimizes using objectively verifiable rewards.
> - **GRPO** compares a group of model responses and reinforces relatively better ones.
> - Transformers process token embeddings through repeated blocks containing **self-attention + feed-forward networks**.
> - The LM head turns the final representation into probabilities over possible next tokens.
> - **Context length** limits how much information an agent can place inside the model at once.
> - **KV caching** avoids repeatedly recomputing attention information for old tokens.
> - Self-attention uses **Q, K, and V** to identify relevant context and combine information.
> - **MLA** reduces KV-cache size using compressed latent representations.
> - **DSA** reduces attention computation by selecting only highly relevant tokens.
> - **MoE** replaces dense FFNN computation with a router and selected experts.

## From Language Modeling to Powering Agents

An LLM begins as a general **base language model**. Later (post) training gives it behaviors needed for practical interaction and agent systems.

Important agent-oriented capabilities include: *following instructions, system prompts, multi-turn conversations, structured outputs, reasoning behavior, tool calling.*

These are largely developed during **post-training**.
### System Prompt

A **system prompt** is a privileged instruction describing how the model should behave.
![[2. LLMs and AI Agents-1789659520208.webp]]
The system prompt is placed before the user's instructions and has a higher-priority role in determining behavior.

> [!question] Why system prompts matter ?
> 
> They allow the organization deploying an LLM to specify: expected behavior, response format, available tools, restrictions, role/personality, other operational instructions. without retraining the underlying model.
> 
> > **Training changes the model.**
> > **System prompts configure how an already-trained model is used.**
### Multi-turn Conversations

LLM interfaces commonly represent interaction as a sequence of messages:

This allows the model to distinguish:

- who said something,
- what happened earlier,
- what the current question refers to.

==Conversation history therefore gives the model a limited form of conversational memory.==
### Tool Use

An LLM can generate a specially formatted output representing an **action**.

Example conceptually:
![[2. LLMs and AI Agents-1789803263619.webp]]

The surrounding agent software:
1. detects the tool call,
2. executes the software function,
3. retrieves its result,
4. sends the result back to the LLM.

Therefore:
```text
LLM does not directly execute the tool
              ↓
LLM generates a tool-call request
              ↓
Agent software executes it
```

Available tools are commonly provided to the model as part of its instructions/context.
> [[5. Frameworks, Extensions and Debugging]]
### Thought → Action → Observation loop

- Thought --> Internal/model reasoning associated with the step.
- Action --> An action the agent wants to perform, typically a tool call.
- Observation --> The result returned after an action executes.
- Answer --> The final response produced when no further action is required.
# Training a Large Language Model

LLM training has two major phases:

![[2. LLMs and AI Agents-1789806085530.webp]]

Post-training itself includes techniques such as: `SFT + Reinforcement Learning`
## Pre-training — Language Modeling

Pre-training teaches the model through **next-token prediction** and This creates the base model.

![[2. LLMs and AI Agents-1789806127368.webp]]

The model:

1. predicts a token,
2. compares its prediction against the actual token,
3. calculates a loss,
4. updates its weights,
5. repeats this process over enormous datasets.

Training data can include web text, books, code, other curated text sources. This process occurs an enormous number of times and produces a **base model**.

> [!tip]  
> Pre-training primarily teaches the model statistical patterns contained in massive amounts of language data.
## Post-training

> [!tldr]
> - **SFT — Supervised Fine-Tuning:**  
>     “Here is the correct answer. Learn to imitate it.”  
>     Humans provide example questions and good answers, and the model learns from them.
> - **RLHF — Reinforcement Learning from Human Feedback:**  
>     “Here are several answers. Which one do humans prefer?”  
>     Humans rank or rate responses, and the model learns to produce answers people judge as better.
> - **RLVR — Reinforcement Learning with Verifiable Rewards:**  
>     “Try to solve it, then automatically check whether the answer is actually correct.”  
>     Instead of relying mainly on human preference, a verifier can check things like math answers, code tests, or other objectively testable results.
> 
> > **SFT = imitate examples → RLHF = satisfy human preferences → RLVR = optimize for checkable correctness.**
### Supervised Fine-Tuning

Base models contain many latent capabilities but may require difficult prompting to use effectively.

**Supervised Fine-Tuning (SFT)** (also called Instruction tuning) teaches more desirable instruction-following behavior.

Training examples contain: `Prompt + Desired completion`

![[2. LLMs and AI Agents-1789810937615.webp]]

Both prompt and response enter the model as context. However, the training loss is applied primarily to the **completion tokens**, not the prompt tokens.

Conceptually:

```text
Prompt tokens
    ↓
Context only

Completion tokens
    ↓
Training target / loss
```

> [!tldr]-
> **Pre-training = learn language.**  
> **SFT = learn how to respond.**
> 
> ### Mental model
> 
> Think of teaching a student:
> 
> **Pre-training:**
> 
> > Read millions of books and learn how language works.
> 
> ```text
> "The cat sat on the..." → "mat"
> ```
> 
> The model learns to **predict the next token** across lots of text.
> 
> **SFT:**
> 
> > Now practice answering questions the way we want.
> 
> ```text
> User: What is 2 + 2?
> Assistant: 4
> ```
> 
> The model sees the **whole prompt**, but we calculate the training loss mainly on the **desired answer**:
> 
> ```text
> [User: What is 2 + 2?] [Assistant: 4]
>         context              ↑
>                          loss here
> ```
> 
> ### The one thing to remember
> 
> > **Pre-training teaches the model what text looks like.  
> > SFT teaches the model what a good response looks like.**
> 
> The underlying learning mechanism is almost the same: **predict tokens → calculate loss → backpropagate → update weights.**
> 
### Reinforcement Learning

> [[10 - Reinforcement Learning]]

SFT shows the model what a desired response looks like. Reinforcement learning instead evaluates generated responses using a **reward**.

```text
Model generates output
        ↓
Output receives reward
        ↓
Model updated toward higher-reward behavior
```
#### RLHF

**RLHF = Reinforcement Learning from Human Feedback**

Preference may come from humans or reward models

The training process increases the probability of preferred behavior and decreases the probability of rejected behavior.
![[2. LLMs and AI Agents-1789811069216.webp]]

RLHF can influence things such as:

- response style,
- response length,
- helpfulness,
- safety behavior,
- other human preferences.
#### RLVR

**RLVR = Reinforcement Learning with Verifiable Rewards**

Instead of relying only on subjective preferences, outputs are evaluated using something that can be checked automatically.

Examples:

```text
Did it use the correct format?
Did it produce the correct mathematical answer?
```

This works especially well when correctness is objectively verifiable.

![[2. LLMs and AI Agents-1789811109285.webp]]
### Group Relative Policy Optimization — GRPO

GRPO provides an example of RL with verifiable rewards. Suppose the desired output is:

```xml
<answer>42</answer>
```

A response may receive separate rewards.
![[2. LLMs and AI Agents-1789811205277.webp]]
#### Group-based comparison

GRPO does not generate only one response. It generates a **group of responses** for the same prompt.

Example:

```text
Prompt
├── Response 1 → reward
├── Response 2 → reward
├── Response 3 → reward
├── Response 4 → reward
└── Response 5 → reward
```

Responses are compared relative to the group. Higher-performing responses are reinforced.

> The word **Group** in GRPO comes from comparing multiple responses produced for the same prompt.
# Transformer Architecture

> [[Attention is All You Need (Transformers)]]

Most modern LLMs are based primarily on the **Transformer decoder architecture**.

Three major components are:
![[2. LLMs and AI Agents-1789811529168.webp|730]]
## Tokenizer

Converts text into tokens/token IDs. (Text -> Token IDs)
A tokenizer has a fixed **vocabulary**.

Example: `Vocabulary size = 50,000`

Each token has a corresponding numeric vector called an **embedding**. (Token -> Token ID -> Embedding vector)
## Transformer blocks

Most of the actual processing occurs inside a stack of Transformer blocks.
## LM Head

The final representation is passed into the **language modeling head**.

The LM head produces a probability distribution over the vocabulary.

Example:

```text
Token A → 0.40
Token B → 0.25
Token C → 0.10
...
```

The model then needs a **decoding strategy** to choose an output token.

> [!info] Decoding Strategy
> We may choose the highest probability token, but there are often good reasons for picking other tokens. The method to pick tokens from the probability distribution is called a decoding strategy.
## Decoding and Temperature

The probability distribution does not automatically mean the highest-probability token must always be selected.

A decoding strategy determines the selection process.

Temperature = 0 --> Roughly: `Always choose highest-probability token` More deterministic.
### Higher temperature

Allows more sampling from the probability distribution.
- High-probability tokens → still more likely
- Lower-probability tokens → greater chance than before
This increases output diversity.
## Processing Through Transformer Blocks

A neural network processes input through a **forward pass**.

For a Transformer:

![[2. LLMs and AI Agents-1789812359998.webp]]

Each token can be imagined as having its own processing track.

For next-token generation, the representation associated with the **last token** is used to predict the next token.

However, that representation contains information gathered from earlier tokens.
## Context Length

The maximum number of token positions available to a model forms its **context length**.

Example: `Context length = 100,000 tokens`

means roughly that the model can work with a sequence within that token budget.

This directly affects agents because the context may need to contain:

- system instructions,
- conversation history,
- retrieved documents,
- tool descriptions,
- tool results,
- memory,
- current task,
- generated output.

This produces the problem of Context Engineering.

> [!info] **Context engineering** 
> Deciding which information should be placed in the model's limited context so it has the most relevant information for the current task.
## KV / Prompt Caching

During the first forward pass, the model processes all input tokens.
During autoregressive generation, recalculating everything for every new token would be wasteful.

Previously computed information can therefore be cached.

Names include: prompt caching, prefix caching, KV caching

Conceptually:

![[2. LLMs and AI Agents-1789812192782.webp]]

Benefits: lower computation, faster generation, lower latency, improved inference economics.
## Inside a Transformer Block

A Transformer block contains two major components:

```text
Self-Attention
      ↓
Feed-Forward Neural Network
```

Simplified intuition:
![[2. LLMs and AI Agents-1789812465766.webp]]
## Feed-Forward Neural Network

The feed-forward network processes each token representation. A typical dense FFNN:

```text
Input representation
       ↓
Expand to larger hidden dimension
       ↓
Transform
       ↓
Compress back
```

The learned weights encode patterns acquired during training.

A simplified example:

```text
"The Shawshank"
       ↓
association
       ↓
"Redemption"
```

This illustrates how learned language/factual associations may be encoded in model parameters.
## Dense Models vs Mixture-of-Experts

A **dense model** activates the same large feed-forward network for every token.
A **Mixture-of-Experts model** contains multiple smaller FFNNs:
![[2. LLMs and AI Agents-1789812596834.webp]]
Only selected experts process a given token. MoE is covered in more detail in Part 2.
## Self-Attention — High-Level Intuition

Words depend heavily on context.

Example: bank
could mean: financial institution
or: riverbank

Self-attention lets the representation of one token incorporate information from other relevant tokens.

Example: The dog chased the llama because it...

To understand `"it"`, the model must determine which earlier token is relevant.

Self-attention performs two broad operations:
![[2. LLMs and AI Agents-1789812972332.webp]]
1. Relevance scoring
	- Determine which previous positions matter.
2. Information combining
	- Mix information from those positions into the current token's representation.

# A Deeper Dive Into Large Language Models

## How Self-Attention Works

Self-attention begins with vectors representing the tokens.

Three learned projection matrices transform these representations into:

Intuition:
- Q -> Query: What information am I looking for?
- K -> Key: What information do I contain / when am I relevant?
- V -> Value: What information should I contribute if selected?
### Relevance Scoring

For the token currently being processed, its **query** is compared with the **keys**.
![[2. LLMs and AI Agents-1789813271487.webp]]
Conceptually:

```text
Qcurrent × K₁
Qcurrent × K₂
Qcurrent × K₃
...
```

This produces attention/relevance scores.

High score: `this token is highly relevant`
Low score: `this token contributes little`
### Combining Information

After relevance scores are calculated, they weight the corresponding **value vectors**.

Conceptually:
![[2. LLMs and AI Agents-1789813322059.webp]]
The resulting vector becomes the enriched contextual representation.

The standard attention equation is:
```text
Attention(Q, K, V) = softmax(QKᵀ / √dₖ)V
```

Flow:
![[2. LLMs and AI Agents-1789813352872.webp]]
## KV-Caching Revisited

During text generation, previously seen tokens do not change.

Naive attention would repeatedly recalculate their:

```text
K vectors
V vectors
```

for every new generated token. That is redundant. Instead:

```text
previous K → cache
previous V → cache
```

Then for the newest token we mainly need to compute its new information and use the cached history.

Importantly, previous **Q vectors do not need to be cached** in the same way because attention generation requires the query for the current token.
![[2. LLMs and AI Agents-1789813522371.webp]]
![[2. LLMs and AI Agents-1789813537021.webp]]
### KV cache trade-off

- **Benefit**: Less repeated computation → faster inference
- **Cost**: Store K + V for many tokens → high memory usage

Therefore a major goal of newer attention architectures is: Reduce KV-cache memory + Reduce attention computation
## More Efficient Self-Attention

Several approaches attempt to improve attention efficiency.

The chapter mentions:

```text
Grouped-Query Attention — GQA
Multi-Query Attention — MQA
FlashAttention
Multi-head Latent Attention — MLA
DeepSeek Sparse Attention — DSA
```

The later sections focus mainly on **MLA** and **DSA**.
## Multi-head Latent Attention — MLA

Standard Multi-head Attention can require large amounts of KV-cache memory.

**MLA** reduces this by compressing keys and values into a lower-dimensional latent representation.

Instead of caching: `Full K + Full V`
MLA caches something closer to: `Compressed latent KV

Conceptually:

```text
Input
 ↓
Low-rank compression
 ↓
Latent KV
 ↓
Cache
```

Because the cached representation is smaller:

```text
KV-cache memory ↓
Inference efficiency ↑
```

---

## MLA and positional information

MLA also has to account for positional information.

The chapter discusses **Rotary Position Embedding (RoPE)**.

The important intuition is that positional information is handled carefully so that it does not destroy the benefit of caching the compressed latent representation.

### Simplified MLA intuition

```text
Input embedding
      ↓
Compressed latent representations
      ↓
Small latent KV cached
      ↓
Content + positional information
      ↓
Multi-head attention
```

# 34. MHA vs GQA vs MQA vs MLA

## MHA — Multi-Head Attention

```text
Separate K/V structures across attention heads
```

High expressiveness but larger KV memory.

## GQA — Grouped-Query Attention

Groups query heads so some K/V representations can be shared.

```text
Less KV memory
```

## MQA — Multi-Query Attention

Shares K/V even more aggressively.

```text
Even lower KV requirements
```

## MLA — Multi-head Latent Attention

Rather than simply sharing K/V, it caches a compressed latent representation.

```text
Full KV
  ↓ compression
Latent KV
  ↓
cache
```

> [!key]  
> The fundamental MLA idea is **compression of the KV cache**.

# 35. DeepSeek Sparse Attention — DSA

MLA reduces the amount of information stored.

DSA attacks another problem:

```text
Do we need to attend to every previous token?
```

DeepSeek Sparse Attention selects only a subset of relevant tokens.

Two key components are:

```text
Lightning Indexer
+
Top-K Selector
```

---

## Lightning Indexer

Estimates how relevant previous tokens are to the current query.

```text
Query
  ↓
Lightning Indexer
  ↓
relevance scores
```

---

## Top-K Selector

Selects only the highest-scoring positions.

```text
All previous tokens
       ↓
relevance ranking
       ↓
Top K tokens
       ↓
full attention
```

The chapter's example uses:

```text
K = 2,048 tokens
```

rather than attending to the entire context.

### Main result

```text
Normal attention:
attend to many/all previous tokens

DSA:
identify important tokens
        ↓
attend only to Top-K
```

This substantially reduces attention computation.

# 36. Mixture of Experts — MoE

MoE replaces a single dense feed-forward network with multiple smaller networks called **experts**.

Two major components:

```text
Experts
+
Router / Gate Network
```

---

## Experts

Each expert is essentially a feed-forward neural network.

Different experts may learn to specialize in different patterns.

The precise interpretation of their specialization is not always straightforward.

---

## Router

The router decides which experts should process a token.

```text
Token representation
       ↓
Router
       ↓
Probability over experts
       ↓
Select top expert(s)
       ↓
Selected experts process token
```

The router has learned weights.

After processing the token representation, a softmax produces something like:

```text
Expert 1 → 0.45
Expert 2 → 0.30
Expert 3 → 0.15
Expert 4 → 0.10
```

The required number of highest-scoring experts is selected.

---

# 37. Expert Load Balancing

A problem appears if the router repeatedly chooses the same experts.

Then:

```text
Popular experts
→ heavily trained

Other experts
→ undertrained
```

This requires **load balancing**.

Two techniques discussed are:

```text
Expert capacity
Auxiliary loss
```

---

## Expert Capacity

Each expert can process only a limited number of tokens in a batch.

Example:

```text
Expert 1 capacity reached
           ↓
new token cannot go there
           ↓
route to next-highest expert
```

This encourages work to be distributed.

---

## Noise and Auxiliary Loss

Another method is to modify router behavior.

Small amounts of noise may be introduced before routing decisions to create variation.

More sophisticated systems use an **auxiliary loss**.

The auxiliary loss can reward:

```text
balanced expert usage
```

and penalize:

```text
repeated concentration on the same experts
```

---

# 38. Sparse Parameters vs Active Parameters

A critical MoE distinction is:

```text
Total / sparse parameters
vs
Active parameters
```

All experts generally need to be available in memory.

However, only a subset executes for a given token.

Example:

```text
Model has 30B total parameters
        ↓
only 3B active during a forward pass
```

So MoE does **not necessarily reduce the amount of model memory required**.

Instead, it can drastically reduce the amount of computation performed for each token.

> [!important]  
> **Sparse parameters** = total parameters that must exist/be loaded.
> 
> **Active parameters** = subset actually used during a particular forward pass.

# 43. Key Distinctions to Remember

| Concept A      | Concept B          | Difference                                                               |
| -------------- | ------------------ | ------------------------------------------------------------------------ |
| Token          | Word               | Tokens can be words, subwords, punctuation, etc.                         |
| Base model     | Post-trained model | Base model comes from pre-training; post-training shapes useful behavior |
| SFT            | RL                 | SFT provides desired completions; RL optimizes using rewards             |
| RLHF           | RLVR               | Human/preference-based rewards vs automatically verifiable rewards       |
| Thought        | Action             | Model processing/reasoning vs operation to perform                       |
| Action         | Observation        | Tool request vs result returned by tool                                  |
| Step           | Trajectory         | One agent operation vs sequence of operations                            |
| Context length | KV cache           | Maximum working sequence vs cached attention state                       |
| Self-attention | FFNN               | Gathers contextual information vs transforms representations             |
| K/V cache      | Q                  | Previous K/V are reused; current query is needed for new attention       |
| Dense model    | MoE model          | All FFNN parameters active vs selected experts active                    |
| Sparse params  | Active params      | Total model parameters vs parameters used for the current computation    |
| MHA            | MLA                | Full multi-head K/V vs compressed latent KV                              |
| MLA            | DSA                | Compress what is cached vs reduce which tokens receive full attention    |

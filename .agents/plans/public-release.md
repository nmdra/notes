# Plan: Prepare this repository for public release

## Goal

Make `nmdra/notes` public without unintentionally exposing credentials, private notes, private metadata, or restricted third-party material. Review the current tree, reachable Git history, and GitHub-hosted records before changing visibility. Current-file implementation is approved. The owner subsequently approved deletion of the 70 old Actions runs, retention of the cache, source-repository variable configuration, and publication with existing history retained after pushing the fixes and verifying CI. Git history rewriting and force-pushing are not authorized.

## Audit result

**Visibility conversion is authorized after CI passes.** The owner explicitly accepted historical content remaining in existing commits. The 70 old Actions runs have been deleted with approval. No confirmed authentication credential leak was found in the local scan. That result is not proof that all content is safe.

Audit baseline: `589c127`. The working tree was clean before this plan was created.

### Confirmed publication concerns

1. **Historical content remains accessible.** Commit `4304e6d` contains 156 paths under `content/`, including notes and binary attachments. Commit `5f27346` removed Harness Engineering material and excluded it from site publication. Commit `470fc4f` stopped tracking the remaining content. Those deletions do not remove earlier versions from Git history. Evidence: `git ls-tree -r --name-only 4304e6d content/`, and the changes in those three commits. These files need privacy and redistribution review, not only a secret scan.
2. **Tracked internal plans reveal local paths and vault details.** `.agents/HOMEPAGE_PLAN.md:10,30,497-500` and `.agents/VISUAL_IMPROVEMENTS_PLAN.md:14-31` contain absolute local links. `.agents/PLAN.md:12-29,71-72` records a local vault location, private repository identity, storage structure, and old publishing details. These are metadata disclosures, not credentials. Decide what to retain or sanitize. Removing current files alone does not remove historical versions.
3. **Sync output includes unpublished filenames.** `scripts/sync-content.py:477-493` prints blocked document paths, outside-publication targets, unresolved references, and referring notes. CI runs this report without `--quiet` (`.github/workflows/deploy.yml:57-60`). GitHub states that Actions history and logs become visible when a repository becomes public. Existing runs therefore need review before the switch, even if future reporting is fixed.
4. **Private-vault identity and publishing rules are visible in source.** `README.md:28,66`, `.github/workflows/deploy.yml:34-55`, and `publish.list:6-19` disclose the source repository and selected/excluded folder names. Git commit metadata also contains a personal author email, for example in `4304e6d`. These may be intentional, but require owner approval.

### Publication-boundary hardening opportunities

These are code-level exposure paths, not proof that sensitive files currently exist in the external vault.

- **Local file symlinks:** `Vault.all_files` enumerates files and `Vault.read` follows `is_file()`/`read_bytes()` without a resolved-path boundary check (`scripts/sync-content.py:156-180`). A publishable symlink can read outside an included folder or outside the vault. Git-tree mode does not examine entry modes. Reject symlink entries consistently rather than interpreting a Git symlink blob as note content.
- **Hidden-file inconsistency:** worktree enumeration rejects hidden components, while Git enumeration includes them. The copy loop checks only parent components (`scripts/sync-content.py:156-168,374-378`). A hidden Markdown filename can pass in Git-tree mode.
- **Canvas review gap:** canvases are copied as allowed assets, but reference scanning only reads Markdown (`scripts/sync-content.py:40-56,395-398`; `quartz.config.yaml:161-162`). Embedded canvas text and private target names need explicit review. Do not treat broken-link UI as redaction.
- **Asset exception:** referenced allowed media can come from outside included note folders unless explicitly excluded (`scripts/sync-content.py:414-426`). This supports the shared attachment directory. The README's claim that everything outside listed folders stays private is too broad (`README.md:9-22`). Review these attachments, including screenshots and embedded metadata.
- **Limited output gate:** `scripts/check-blocked-files.py:10-19` checks blocked suffixes only. It does not certify that notes, canvas text, allowed images, or generated indexes are free of sensitive data.
- **Trusted publication branch:** the workflow checks out the private vault before repository scripts, dependency installation, tests, and build run (`.github/workflows/deploy.yml:46-93`). Anyone who can land executable changes on `v5` can potentially read the checked-out vault. Public visibility alone does not grant that access. Keep untrusted pull-request code out of this privileged workflow.

### Existing protections and scan evidence

- No tracked `content/` files at HEAD. `.gitignore:17-25` excludes generated content; public output, dependencies, and browser artifacts are also ignored. Ignored local directories do not automatically become public when remote visibility changes.
- No tracked `.env`, private-key, credential-file, log, or database filename matches were found in the 191-file current tree. `.npmrc:1-2` contains package settings, not authentication configuration.
- Local history is not shallow. Local refs are `v5`, `origin/v5`, and `origin/HEAD`, at the same baseline. There are 57 reachable commits and 498 unique historical paths. Remote-only refs were not fetched.
- Gitleaks scanned 56 commits, approximately 17.46 MB, using `gitleaks git --no-banner --redact --report-format json --report-path - --log-opts='--all' .`. Its two findings are historical occurrences of the same Cloudflare analytics identifier in `quartz.config.yaml:9`, in `4239fda` and `bef126f`. This value is intentionally emitted in browser HTML by `quartz/components/renderPage.tsx:368-374`; it is not evidence of an authentication-token leak. Do not rotate it solely because of the generic scanner finding.
- A supplemental history pattern scan inspected 617 blob/path pairs. Four credential-like documentation examples were identified, with no confirmed real credential. Automated scans do not assess image contents, copyright, or all private information.
- Both checkout steps disable persisted credentials, Actions have SHA-pinned references, workflow contents permissions are read-only, and deployment write permissions are isolated (`.github/workflows/deploy.yml:14-15,27-55,158-164`). `REPO_KEY` is a secret reference, not a committed secret value. Its actual scope and expiry were not inspected.
- `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts -p 'test_*.py'` passed all 7 tests. One expected missing-template error is printed by a negative test. No sync, site build, or live deployment was run.

## Decisions

- **Approved execution scope:** fix current files first. The owner subsequently authorized a read-only review of hosted records and explicitly declined a Git history rewrite. Historical note/attachment removal is therefore not performed; old commits remain a release blocker. Hosted-record deletion still requires separate approval. Sanitize private operational metadata in current documentation and replace the hardcoded vault repository with `VAULT_REPOSITORY` configuration. The owner must set that variable before the next deployment; checkout logs may still disclose its value.

- **Release is gated on owner review of history and hosted records.** A clean HEAD and a clean credential scan are not sufficient. Do not rewrite history or delete GitHub records without separate approval.
- **Keep the existing private vault private.** The public repository is a publishing tool, not a copy of the whole vault. Do not inspect or include additional private vault material as part of this plan without permission.
- **Use public-safe logs by default in CI.** Prefer counts and a success/failure result. Keep detailed path reports as a local opt-in. Secret masking does not hide arbitrary private filenames.
- **Preserve the intentional shared-media exception, but document it.** Rejecting every asset outside included folders would break the current attachment design. Explicit exclusions must still win.
- **Retain upstream attribution.** `LICENSE.txt:1-21` supplies the Quartz MIT notice. README separately identifies site-content ownership (`README.md:77`). Review note excerpts and images for redistribution rights; a document-extension block does not establish those rights.
- **No infrastructure or dependency redesign in this pass.** Guard trusted publication and add focused boundary tests first. A separate sanitized-content pipeline is a possible later design, not a prerequisite implementation hidden inside this audit.

## Scope

In scope: release privacy decisions, current/historical file review, hosted-log review, safe ignore defaults, reporting changes, focused source-boundary tests, publication-branch protection, and release verification.

Out of scope: automatically making the repository public, deleting files or runs now, rewriting or force-pushing history now, changing the site theme, a full dependency security audit, and reading the external private vault or existing hosted records during this audit.

## Verification and limitations

Acceptance requires an owner-approved historical inventory, reviewed hosted records, no untriaged real credential findings, public-safe CI reports, passing focused boundary tests, and approval of emitted content. A scanner alone cannot certify publication safety.

The initial local audit and current-file implementation did not inspect authenticated GitHub records. A subsequent read-only hosted-record review now covers repository inventories and all 70 retained Actions log archives; see the separate report for limits. Remote-only branch contents were not fetched or rescanned, secret scope/expiry and protection settings were not verified, and the external vault, binary attachments, and fresh emitted site were not reviewed. Those remain release gates. Tests use synthetic temporary vaults only.
